# Model Card: Deepfake Signal Artifact Detector

## Model Overview

Deepfake Signal uses a frame-level artifact detector to estimate whether a face region in an image or video frame contains visual manipulation signals.

The current model is integrated into a browser-based prototype through a local Python backend and a Chrome Extension interface. It is designed to provide a risk signal for visible web media, not a definitive authenticity judgment.

## Intended Use

This model is intended for:

- Research and prototype development
- Browser-based deepfake detection experiments
- Face-localized artifact analysis on visible images or video frames
- Human-in-the-loop review support

This model is not intended for:

- Fully automated moderation decisions
- Legal, forensic, or law enforcement conclusions
- Identity verification
- High-stakes decisions about individuals
- Claims of definitive media authenticity

## Model Architecture

The current artifact detector is based on a ConvNeXt-T style image classification backbone.

The backend first detects faces in the input frame, crops face-centered regions, and runs the artifact detector on each detected face crop. If multiple faces are detected, the final frame-level score is based on the highest face-level fake probability.

Current pipeline:

```text
Input frame
  -> face detection
  -> face-centered crop
  -> ConvNeXt-T artifact detector
  -> face-level fake probability
  -> frame-level risk label
```

## Input

The model receives face-centered image crops extracted from browser-captured frames.

Expected input characteristics:

- RGB image crop
- Face-centered region
- Preprocessed with ImageNet normalization
- Resized according to the backend inference transform

The Chrome Extension sends captured frame crops to the local backend as base64 data URLs.

## Output

The model outputs a probability-like score:

```text
P(fake) in [0, 1]
```

The backend maps this score to user-facing labels:

```text
P(fake) >= 0.95        -> Deepfake_Signal
0.75 <= P(fake) < 0.95 -> Review_Needed
P(fake) < 0.75         -> Safe_Signal
No detected face       -> No_Face
```

For multi-face frames, the system currently uses the highest face-level score as the final frame-level risk score.

## Limitations

Deepfake detection is inherently uncertain. The model may fail or produce unreliable scores under several conditions:

- Very small or low-resolution faces
- Strong motion blur
- Heavy video compression
- Occluded faces
- Extreme lighting conditions
- Non-frontal faces
- Makeup, filters, or beautification effects
- Out-of-distribution generation methods
- Real media with unusual artifacts
- Fake media generated by methods not represented in training data

A low score should not be interpreted as proof that media is authentic.
A high score should not be interpreted as proof that media is fake.

## Bias and Fairness Considerations

The model may perform differently across demographic groups, capture conditions, camera types, and media sources depending on the composition of the training data.

Before deployment in real-world settings, the model should be evaluated for subgroup performance and potential bias.

## Privacy Considerations

The current prototype is designed to run inference through a local backend server. Browser-captured frames are sent to `127.0.0.1` for analysis.

The application does not intentionally store uploaded frames, face crops, or page screenshots. A full privacy policy should be maintained before public release or Chrome Web Store distribution.

## Safety Considerations

The model should be presented as a decision-support tool, not an automated truth detector.

Recommended user-facing language:

```text
This result is a risk signal, not a definitive judgment.
```

Avoid presenting predictions as absolute claims such as:

```text
This media is fake.
This person used a deepfake.
This content is authentic.
```
