# 데이터 전처리 문서 (v2)

딥페이크 탐지를 위한 **얼굴 행동 특징(behavioral feature)** 추출 파이프라인 문서입니다.
원본 영상 → 프레임별 얼굴 분석 → 영상당 고정 길이 시계열(`.npy`)로 변환하는 전 과정을
다룹니다.

---

## 1. 배경 — 왜 다시 전처리했나

기존(v1)은 OpenFace로 뽑은 **AU 강도 17채널**(`[64, 17]`)만 사용했고, 성능이
identity-disjoint 기준 0.549에 머물렀습니다. 확증 실험 결과 병목은 모델이 아니라
**입력 표현(AU 강도)의 정보 부족**이었습니다. 그래서 더 풍부한 표현으로 재전처리했습니다.

- **v1 표현**: OpenFace AU 강도 20개 미만 → `[64, 17]`
- **v2 표현**: Py-Feat **AU 20 + head-pose 3 + emotion 7 = 30채널** → `[64, 30]`

---

## 2. 데이터 소스 (폼/EULA 없이 다운로드 가능한 Kaggle)

| 데이터셋 | Kaggle slug | 구성 | 용도 |
|---|---|---|---|
| FaceForensics++ c23 | `xdxd003/ff-c23` | real 1,000 + 6기법 × 1,000 | 학습·평가 주 데이터 |
| Celeb-DF v2 | `reubensuju/celeb-df-v2` | real 890 + synthesis 5,639 | 학습·평가 |
| DFDC (프레임 크롭) | `ashifurrahman34/dfdc-dataset` | real 76 + fake 305 (영상당 ~10프레임 PNG) | cross-domain 검증용 |

- FF++는 `original`(real) + `Deepfakes/Face2Face/FaceSwap/NeuralTextures/FaceShifter/DeepFakeDetection`(fake) 폴더 구조.
- CelebDF는 `Celeb-real`·`YouTube-real`(real) + `Celeb-synthesis`(fake).
- **주의**: FF++ c23는 H.264로 강하게 압축된 버전입니다. 압축은 주파수(pixel) 기반
  특징의 신호를 파괴하므로, pixel 특징을 쓰려면 비압축(raw) 버전이 필요합니다.

---

## 3. 추출되는 표현

영상 1개 → `data/<video_id>/` 아래 다음 파일:

| 파일 | 형태 | 내용 |
|---|---|---|
| `features.npy` | `[64, 30]` float32 | **행동특징(메인)**: AU 20 + pose 3 + emotion 7 |
| `au_sequence.npy` | `[64, 20]` float32 | AU만 (30ch vs 20ch ablation 대조군) |
| `freq.npy` | `[64, 28]` float32 | **주파수(pixel)특징**: FFT radial 24 + 고주파비 + noise 3 |
| `meta.json` | — | 라벨·소스·기법·컬럼명·skip_frames 등 |

### 30채널 상세
- **AU 20개**: AU01, AU02, AU04, AU05, AU06, AU07, AU09, AU10, AU11, AU12, AU14,
  AU15, AU17, AU20, AU23, AU24, AU25, AU26, AU28, AU43 (0~1 강도)
- **Head-pose 3개**: Pitch, Roll, Yaw (도 단위, ±수십°)
- **Emotion 7개**: anger, disgust, fear, happiness, sadness, surprise, neutral (0~1)

### 주파수 28채널 상세 (프레임당)
- radial power spectrum(방위각 평균) 24 bin + 고주파 에너지 비율 1 + Gaussian-residual
  통계 3(std / |mean| / MSE). 얼굴 크롭에 FFT를 적용해 위조 아티팩트(고주파 지문)를 포착.

## 4. 추출 파이프라인 (디스크 제약 대응, 재개 가능)

Py-Feat의 AU 단계는 **CPU 병목**(GPU 사용률 ~1%)입니다. 그리고 디스크 여유가 제한적이라
**큰 zip을 절대 저장하지 않고 영상 1개씩 스트리밍**하도록 설계했습니다.

```
build_filelist.py  →  make_subset.py  →  stream_extract.py  →  finalize_metadata.py
   (목록·라벨)          (균형 샘플링)        (다운→추출→삭제)        (메타 재생성)
```

### 4-1. build_filelist.py — 목록화 + 라벨링
- Kaggle API로 데이터셋 파일 목록을 받아, **경로 키워드로 라벨** 부여
  (`manipulated`/`synthesis`/기법명 → fake=1, `original`/`real`/`youtube` → real=0).
- 출력: `data/_filelist_<tag>.csv` (컬럼: name, video_id, label, method).
- ⚠️ kaggle 라이브러리는 user-site에 있으므로 이 단계는 **`PYTHONNOUSERSITE=1` 없이** 실행.

### 4-2. make_subset.py — 클래스/기법 균형 서브셋
- real 전량 유지 + fake는 기법별 균등 stride 샘플링(신원 예산 = real 수).
- 출력: `data/_filelist_<tag>_sub.csv`.
- 결과: **FF++ 2,002(real 1,000 + fake 1,002=167×6), CelebDF 1,780(real 890 + synth 890)
  → 합계 3,782개, real 1,890 / fake 1,892 (균형).**

### 4-3. stream_extract.py — 파일 단위 스트리밍 추출 (핵심)
영상 1개마다:
1. **다운로드** — Kaggle 단일파일 엔드포인트를 **경로 완전 URL 인코딩**(`/`→`%2F`, `+`→`%2B`)해 stdlib `urllib`로 받음. (kaggle 라이브러리 불필요 → `PYTHONNOUSERSITE=1` 하에서 동작)
2. **프레임 샘플링** — `auto skip_frames`: 영상 프레임 수를 세어 `round(n/64)` 간격으로 ~64프레임만 검출 (skip=2 대비 3배↓, resample하므로 정보 손실 없음).
3. **Py-Feat 검출** — `detect_video` → Fex(프레임별 AU/pose/emotion).
4. **행렬화** — 프레임별 최대 얼굴 선택, NaN 보간, `[N, 30]` → 64로 resample.
5. **저장 후 즉시 삭제** — `features.npy` + `au_sequence.npy` + `meta.json` 저장, 임시 영상 삭제.
6. **GPU 캐시 정리** — 영상마다 `torch.cuda.empty_cache()`로 메모리 누적(OOM) 방지.

- 동시 디스크 사용 = **영상 1개분(~1MB)** 뿐. 큰 zip 없음.
- **재개 가능**: `features.npy`가 있으면 다운로드 전에 skip.
- **병렬화**: 워커를 필리스트 인덱스로 샤딩(`--num-shards`/`--shard`), GPU 라운드로빈.

### 4-4. finalize_metadata.py — 메타데이터 재생성
- 각 영상의 `meta.json`을 스캔해 `data/dataset_metadata_v2.csv` 재생성
  (여러 워커의 동시 CSV 쓰기 충돌을 피하기 위해 CSV는 마지막에 한 번만 생성).
- 샤드별 에러 로그(`.err_shard_*.jsonl`)를 `errors_v2.jsonl`로 병합.

### 오케스트레이터
```bash
NGPUS=2 SUBSET=1 bash scripts/run_ffpp_celebdf.sh   # GPU 0,1만 사용, 균형 서브셋
```
- 성능 실측: py-feat ~167 core-초/영상. GPU당 8워커가 최적(더 늘리면 GPU 메모리 누적→OOM).
- 16워커/2GPU에서 ~0.22 vid/s → 서브셋 3,782개 ≈ 수시간.

## 5. DFDC 프레임 추출 (extract_dfdc_frames.py)

DFDC는 영상이 아니라 **얼굴 크롭 PNG**(`<hash>_<frame>.png`)로 제공됩니다.
- 같은 hash 프레임들을 모아 순서대로 `detect_image` → `[N, 30]` → 64로 resample.
- 라벨: `fake` 폴더 → 1, `real` → 0. video_id = `dfdc_<label>_<hash>`.
- 출력: FF++/CelebDF와 동일 포맷(`features.npy`/`au_sequence.npy`/`meta.json`) +
  `data/dataset_metadata_dfdc.csv`.
- **신원 정보 없음** → split은 영상 단위(각 hash가 자기 그룹).

---

## 6. 주파수(pixel) 특징 추출 (extract_freq.py) — CPU 전용

행동특징이 놓치는 위조 아티팩트를 잡기 위한 주파수 특징. Py-Feat/GPU 불필요.
- **FF++/CelebDF**: 영상을 재스트리밍 → cv2로 프레임 읽기 → **Haar 얼굴 검출 후
  0.4 마진으로 크롭(블렌딩 경계 포함)** → 128×128 그레이스케일 → FFT → 28채널.
- **DFDC**: 이미 크롭된 PNG에서 직접 계산.
- 출력: `data/<video_id>/freq.npy` `[64, 28]`.
```bash
WORKERS=24 bash scripts/run_freq.sh              # FF++/CelebDF 재스트리밍
$PY scripts/extract_freq.py --from-crops .dfdc_dl/Dataset   # DFDC 크롭
```
- ⚠️ FF++ c23 압축 탓에 주파수 신호가 약함(단독 AUC ~0.53). 비압축 데이터에서 유효.

## 7. 라벨링·신원 파싱·스플릿

### video_id 규칙
- FF++: `ffpp_<method>_<core>` (예: `ffpp_real_000`, `ffpp_Deepfakes_000_003`)
- CelebDF: `celebdf_<method>_<core>` (예: `celebdf_real_id0_0000`, `celebdf_synthesis_id0_id1_0000`)
- DFDC: `dfdc_<label>_<hash>`

### 신원(identity) 파싱 (`src/au_detect/data/identity.py`)
- FF++: `000_003` → {ff_000, ff_003} (target·source 쌍)
- CelebDF: `id0_id1` → {celeb_id0, celeb_id1}; YouTube-real → {yt_<번호>}
- DFDC: hash 전체 = 1개 신원(영상 단위)
- faceswap/reenactment fake가 두 신원을 연결 → union-find로 연결성분(component) 구성.

### identity-disjoint 스플릿 (`src/au_detect/data/splits.py`)
- 연결성분 단위로 train/val/test에 통째 배정(그리디 bin-packing, seed 42).
- **한 신원이 두 split에 걸치지 않음을 assert**, 각 split에 양 클래스·양 소스 존재 검증.
- 결과(`outputs/v2/splits.csv`): 1,387 신원, **leak 0**, train/val/test = 78.3/11.0/10.7%.

## 10. 주의사항 (실전 gotcha)

- **Py-Feat 0.6.2 API**: 컬럼은 `fex.aus` / `fex.poses` / `fex.emotions` 속성으로 접근
  (구 `fex.au_columns` 등은 없음). `detect_video` 결과의 `frame`이 인덱스이자 컬럼이라
  groupby 전에 `reset_index` 필요.
- **스레드 경합**: 워커가 많으면 torch/BLAS 스레드 과구독으로 급격히 느려짐
  → `torch.set_num_threads(1)` + `OMP/MKL/OPENBLAS_NUM_THREADS` 제한 필수.
- **워커 종료 확인**: `pgrep -f <script>`가 자기 셸을 오탐하므로, 종료는 GPU 메모리
  해제(`nvidia-smi`)로 검증. 고아 워커는 `pkill -9 -f <script>`.
- **채널 수 변경**: v2 `au_sequence.npy`는 **[64,20]**(구 [64,17] 아님). 다운스트림
  모델·스플릿이 채널 수를 가정하면 수정 필요.
- **c23 압축**: 주파수 특징을 쓸 계획이면 비압축 데이터 확보 필요.
